# S7 export contracts

The dossier has one composition source and three presentations: the in-app
preview, the JSON download and the self-contained HTML download. The browser
does not recompute counts for any of them.

## HTTP endpoint

```
POST /api/datasets/{dataset_id}/reports/dossier?format=json
POST /api/datasets/{dataset_id}/reports/dossier?format=html
```

Both accept the same JSON body:

```json
{
  "sections": ["summary", "provenance", "study", "audit", "scorecard",
               "findings", "comparison", "models", "limitations",
               "reproducibility"],
  "audit_run_id": "run-…",
  "comparison_run_id": "run-…",
  "model_run_ids": ["run-…"]
}
```

* `sections` is optional; omitted means all ten in catalogue order.
* Unknown sections and an empty selection are `422 validation_error`.
* An audit/comparison/model ID belonging to another dataset is `404
  not_found`.
* A run ID of the wrong kind is `422 validation_error` with the actual kind in
  `details`.
* Duplicate model IDs are de-duplicated while preserving the first request
  order; the server still returns sections in its own catalogue order.
* `format` other than `json`/`html` is a validation failure, not a fallback.
* Downloads use `Content-Disposition: attachment` with
  `splitscope-dossier-<sanitised-dataset>.<json|html>`, `Cache-Control: no-store`
  and `X-Content-Type-Options: nosniff`.

## JSON shape

Schema version: **`1.0.0`** (`DOSSIER_SCHEMA_VERSION`). Top-level fields:

| Field | Meaning |
|---|---|
| `report_kind` | Always `dossier` |
| `schema_version` | `1.0.0` |
| `generated_at_utc` | UTC generation timestamp |
| `app` | `{name, version}` |
| `title` | `SplitScope evidence dossier — <dataset>` |
| `dataset` | ID, name, source, synthetic flag, SHA-256, rows, columns |
| `request` | Effective sections and run IDs resolved by the server |
| `summary` | Real counts, split, headline, analyses, key findings, cautions |
| `sections` | Object keyed by section ID; each has `id`, `title`, `description`, `included`, `available`, `reason`, `data` |
| `included_sections` | Requested sections in server catalogue order |
| `integrity` | Embedding policy and fingerprint caveat |
| `reproducibility` | Schema/app versions, generation time, IDs, fingerprint, versions and storage note |
| `section_catalogue` | Ordered catalogue metadata for clients |

Every requested section is present as a key. If its source is absent,
`available` is `false`, `data` is `null`, and `reason` names the missing run. It
is never returned as an empty-but-available result.

The summary is derived from the same selected audit/comparison/model objects. It
reports exact finding counts, evaluated-check count, not-evaluated count, model
count, per-severity counts and the audit headline; the UI does not add another
number layer.

### Embedding policy

```json
{
  "raw_data_embedded": false,
  "row_predictions_embedded": false,
  "bounded_evidence_embedded": true,
  "note": "The full uploaded dataset and row-level test predictions are not embedded. Findings carry only the bounded evidence examples already stored in the audit run. A SHA-256 fingerprint identifies bytes; it is not anonymisation."
}
```

Only the bounded examples already stored by the audit are embedded. Full rows,
uploaded bytes and row-level test predictions are not. The fingerprint is an
identity check, not anonymisation.

## Printable HTML

`format=html` renders the same object through
`backend/app/reports/dossier_html.py`:

* starts with `<!doctype html>`, ends with `</html>`;
* no `<script>`, external CSS, fonts, images or network requests;
* inline CSS only; the document opens and prints offline;
* every text value passes through `html.escape` unless it is markup generated by
  this renderer;
* the only raw table cells are severity badges produced by `_badge`; an explicit
  `raw={0}` allowlist prevents user text from bypassing escaping;
* `@media print` supplies page margins, hides the contents strip, keeps
  findings/models/tables from breaking across pages and forces paper colours for
  the cover;
* a cover, section headings, evidence tables, callouts, model cards, scorecard,
  limitations and the integrity footer mirror the preview;
* unavailable requested sections render a dashed “Not available” box with the
  reason.

The HTML visual regression test checks that the actual badge markup is present
and that escaped `<span class="badge…>` text is **absent**.

### PDF

There is no server-side PDF library. **Print / Save as PDF** opens the browser's
print dialog on the in-app paper with the same print rules; the downloaded HTML
is the portable equivalent. SplitScope does not claim a binary PDF export.

## Compatibility

The earlier per-run routes remain unchanged:

* `POST /api/reports/json` — single audit/comparison JSON;
* `POST /api/reports/html` — single audit/comparison self-contained HTML;
* `GET /api/assignments/{id}/download` (via the stored handles) — split
  assignment CSV with the spreadsheet-injection prefix policy.

Their labels and file behaviour are preserved in the archive below the studio.

## Tests

`backend/tests/test_dossier.py` (10 tests) independently checks complete
composition, missing-source states, not-evaluated preservation, HTML/JSON
exports, section ordering/non-empty validation, wrong-kind/foreign-dataset
refusal, predictive-run held-out metrics and subgroup caveats, hostile
study-title escaping, the badge-markup regression and direct builder
determinism.

`frontend/tests/ReportPreview.test.tsx` (5 tests) checks that the renderer shows
server counts, preserves unavailable reasons, limits the contents strip to
included sections and escapes study text. `frontend/e2e/s7-report-studio.spec.ts`
downloads both formats from the live UI and independently inspects the JSON and
HTML, including the absence of scripts and the presence of the selected model
run.
